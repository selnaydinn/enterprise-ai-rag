# Enterprise AI

A **Retrieval-Augmented Generation (RAG)** application for asking questions about Turkish regulation PDFs.
Users upload PDFs, ask questions in natural language and get answers generated by Gemini **from the uploaded
documents only**, together with the source file and page each answer is based on.

**Stack:** FastAPI · ChromaDB · `intfloat/multilingual-e5-base` embeddings · `mmarco-mMiniLMv2` cross-encoder reranker · Gemini 2.5 Flash (via LangChain) · Next.js / TypeScript · Docker

## How it works

```
Upload:  PDF ─► validation ─► PyPDFLoader (per page) ─► blank-line normalization
             ─► RecursiveCharacterTextSplitter (1200 / 300 chars) ─► e5 embeddings ─► ChromaDB

Query:   question ─► "query: " prefix ─► similarity search (10 candidates) ─► score threshold (0.72)
             ─► cross-encoder reranker (best score ≥ −2.0) ─► top 3 chunks in one prompt ─► Gemini 2.5 Flash ─► answer + sources
```

A single FastAPI service (`main.py`, `core/`, `services/`) and a separate Next.js frontend (`rag-frontend/`).
See [docs/development.md](docs/development.md) for the code layout.

## Features

- **Answers with sources:** each answer shows the source file and page; clicking a source opens the PDF.
  If no chunk is relevant enough, Gemini is not called and no tokens are used.
- **Safe uploads:** file name sanitizing, 20 MB limit, PDF content check, duplicates rejected (`409`).
- **Token limit:** a global limit that resets every 6 hours (Turkey time); when reached, the input is locked with a countdown.
- **Login:** single-user password login with a signed, `HttpOnly` session cookie; every endpoint and the PDF files
  require a session, and repeated wrong passwords lock the login for 15 minutes ([docs/api.md](docs/api.md#authentication)).
- **Document deletion:** disabled by default (`ALLOW_DELETE=false`).
- **Startup checks:** the app does not start without `GEMINI_API_KEY`, an existing ChromaDB, or (with login on)
  `APP_PASSWORD` and `SESSION_SECRET`.

## Quick start

Requirements: Docker, Node.js 20.9+ and a Gemini API key. The database and the PDFs are not in git: put the PDFs in
`uploaded_pdfs/` (or start without documents), then build the database once.

```bash
cp .env.example .env          # Windows (cmd): copy .env.example .env  · then set GEMINI_API_KEY, APP_PASSWORD
python -c "import secrets; print(secrets.token_urlsafe(48))"   # put the output in .env as SESSION_SECRET
docker compose build
# Build the database and download the models (about 1.6 GB) into the Docker volume hf_cache;
# add --allow-empty to start without documents
docker compose run --rm rag-backend python scripts/build_db.py --target chroma_db_new --allow-download
# set CHROMA_DIR=chroma_db_new in .env
docker compose up             # backend: http://localhost:8000/docs

cd rag-frontend
npm ci
npm run dev                   # frontend: http://localhost:3000 (sign in with APP_PASSWORD)
```

Open the frontend at `http://localhost:3000`, not `127.0.0.1`: the session cookie only works when the frontend and
the backend use the same host name ([details](docs/configuration.md#frontend-settings-rag-frontendenvlocal)).

With an existing database folder, copy it into the project root instead and set `CHROMA_DIR` to it. See
[docs/configuration.md](docs/configuration.md#chromadb) for the build script and
[the model cache](docs/configuration.md#model-cache).

```bash
python -m unittest discover tests && ruff check .
cd rag-frontend && npx tsc --noEmit && npm run lint
```

Unit tests never use the real Gemini API, ChromaDB, embedding model or network (enforced by `tests/_guards.py`).
CI runs these checks on every pull request to `main`.

## Retrieval quality

Measured on 2026-11-10 with an exact ranking over 4 documents, using the app's flow (10 candidates → e5 threshold →
reranker → top 3):

| | Result |
|---|---|
| Answerable questions (80): evidence at rank 1 / in the top 3 | **75/80** / **79/80** (MRR 0.960) |
| Answerable questions: the chunk with the answer reaches Gemini | **79/80** |
| Unanswerable, close to a document's topic: reach Gemini | 8/44 |
| Unanswerable, unrelated to the documents: reach Gemini | 0/11 |

The reranker made the largest difference: on the first 56 questions, vector search alone puts the evidence first for
39/56 (MRR 0.808), the reranker for 51/56 (0.944). The 24 harder questions added later (paraphrased, distractor on the
same page) are all found at rank 1. The one miss, q23, is a vector-search miss (evidence at vector rank 12, outside the
10 candidates). Article-based chunking (split at "MADDE" headings) was tried and not adopted: it did not beat the
current page-based chunking ([eval/experiment_A_results](eval/experiment_A_results/README.md)).

For unanswerable questions that pass both thresholds, Gemini is asked to reply `BILGI_YOK`, and the app shows the same
"no information" answer. In a manual check of the 8 near-domain ones, 6 got `BILGI_YOK` and 2 an answer saying the
documents contain no direct information; none got an invented answer. Details in [eval/README.md](eval/README.md).

## Known limitations

- **Single user;** one password, no user accounts or per-user token limits. Sessions cannot be revoked one by one
  (changing `SESSION_SECRET` ends all of them). Over plain HTTP the password and the cookie are not encrypted; outside
  `localhost`, run behind HTTPS with `COOKIE_SECURE=true`.
- **No conversation memory;** every question is answered independently.
- **Data leaves the machine;** questions and retrieved chunks are sent to the Gemini API.
- **Questions are logged in full** at `INFO` level (search log in `services/query.py`).
- **Synchronous uploads;** large PDFs are processed during the upload request. A failed upload is rolled back (its
  chunks are deleted, the file is removed), but if the app is stopped while an upload is running, part of its chunks
  can stay in the database and uploading the same PDF again returns `409`.
- **Thresholds tuned on the evaluated questions;** the reranker threshold (−2.0) was chosen on the first 39
  unanswerable questions, where 4/28 near-domain ones reached Gemini; on 16 newer ones it let 4/16 through. The
  reranker adds about 2–3 s per question on CPU.
- **Only retrieval is measured;** answer quality is not evaluated automatically (Gemini's answers were checked by hand
  once).
- **Search after restart;** the approximate vector index is rebuilt when the database is opened and can occasionally
  miss a near chunk ([notes.md](notes.md) item 41). The evaluation uses an exact ranking, so its numbers are not
  affected.
- **Development Docker setup** (`--reload`, full bind mount, root user, no healthcheck); not production-ready. The
  backend port is published on `127.0.0.1` only, so it is not reachable from other devices on the network.
