# Enterprise AI

A **Retrieval-Augmented Generation (RAG)** application for asking questions about Turkish regulation PDFs.
Users upload PDFs, ask questions in natural language and get answers generated by Gemini **from the uploaded
documents only**, together with the source file and page each answer is based on.

**Stack:** FastAPI · ChromaDB · `intfloat/multilingual-e5-base` embeddings · Gemini 2.5 Flash (via LangChain) · Next.js / TypeScript · Docker

## How it works

```
Upload:  PDF ─► validation ─► PyPDFLoader (per page) ─► blank-line normalization
             ─► RecursiveCharacterTextSplitter (1200 / 300 chars) ─► e5 embeddings ─► ChromaDB

Query:   question ─► "query: " prefix ─► similarity search (k=3) ─► score threshold (0.72)
             ─► remaining chunks in one prompt ─► Gemini 2.5 Flash ─► answer + sources
```

A single FastAPI service (`main.py`, `core/`, `services/`) and a separate Next.js frontend (`rag-frontend/`).
See [docs/development.md](docs/development.md) for the code layout.

## Features

- **Answers with sources:** each answer shows the source file and page; clicking a source opens the PDF.
  If no chunk is relevant enough, Gemini is not called and no tokens are used.
- **Safe uploads:** file name sanitizing, 20 MB limit, PDF content check, duplicates rejected (`409`).
- **Token limit:** a global limit that resets every 6 hours (Turkey time); when reached, the input is locked with a countdown.
- **Document deletion:** disabled by default (`ALLOW_DELETE=false`) because there is no authentication yet.
- **Startup checks:** the app does not start without `GEMINI_API_KEY` or an existing ChromaDB.

## Quick start

Requirements: Docker, Node.js 20.9+, a Gemini API key, and a copy of the ChromaDB folder
(`chroma_db_normalization/`) and `uploaded_pdfs/` (not in git).

```bash
cp .env.example .env          # Windows (cmd): copy .env.example .env  · then set GEMINI_API_KEY
docker compose up --build     # backend: http://localhost:8000/docs

cd rag-frontend
npm ci
npm run dev                   # frontend: http://localhost:3000
```

## Tests

```bash
python -m unittest discover tests && ruff check .
cd rag-frontend && npx tsc --noEmit && npm run lint
```

Unit tests never use the real Gemini API, ChromaDB, embedding model or network (enforced by `tests/_guards.py`).
CI runs these checks on every pull request to `main`.

## Retrieval quality

On a 25-question golden set: **Page Hit@3 24/25**, **Evidence MRR 0.766**. All questions come from one document and
there are no unanswerable questions yet. Details in [eval/README.md](eval/README.md).

## Known limitations

- **No authentication;** the token limit is shared by all users and the sidebar user is a placeholder.
- **No conversation memory;** every question is answered independently.
- **Data leaves the machine;** questions and retrieved chunks are sent to the Gemini API.
- **Synchronous uploads;** large PDFs are processed during the upload request.
- **No database setup script;** a new environment needs a copy of the ChromaDB folder.
- **Retrieval tuning;** `k=3` and the 0.72 threshold are not calibrated with negative questions yet.
- **Development Docker setup** (`--reload`, full bind mount, root user); not production-ready.
